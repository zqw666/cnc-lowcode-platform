调研时间：2026-11-02 ｜ 结合项目：前后端分离（MachineMonitor :8888 + C# 子程序 + Omron/Roders/Siemens）｜ 用途：确定低代码应用方向

一、核心结论

工控低代码已分化为三条赛道：OT 侧组态/SCADA 型（Ignition、组态软件）、IT 侧企业级平台（YonBuilder、Mendix）、软硬一体国产新玩家（黑湖、和利时 XMagital）。 "拖按钮控 PLC" 类工具分三档存在，但多步时序 + 多品牌握手类流程（如下料换件）没有现成低代码能直接覆盖。 对本项目，正确方向是：设备控制层保留自研，REST 接口层原样复用，仅将页面/表单/看板层低代码化（首选 amis）。

三、"控 PLC 的低代码"三档对照

市面确实存在控 PLC 的低代码，但能力边界差异极大：

档位代表产品能拖出什么做不到什么适用场景
① 组态软件 组态王、MCGS 昆仑通态、力控、WinCC、Ignition Perspective 拖按钮 → 绑定 PLC 地址 → 写寄存器；动画、报警、趋势 只能"写变量"；多步时序要写脚本，等于换语言编码 单品牌、单机设备的人机界面
② 顺序控制 CODESYS SFC、西门子 GRAPH、LabVIEW、FactoryTalk Optix 拖步序块（S1→S2→S3）编排动作序列，最接近"拖流程控设备" 步内逻辑仍需自写；跨品牌（Omron+Roders+Makino 混合）基本不可行 单一品牌产线的动作序列
③ 流程低代码 Node-RED、Tulip、各类 IIoT 平台 数据管道、上报、简单触发；IT/OT 粘合 不碰实时控制，非确定性，厂商声明不可用于安全逻辑 采集编排、数据上报、边缘转换
关键判定："下料换件"= 探针/夹爪/机器人/CNC 四方握手 + 超时异常分支 + 子程序协同，在任何低代码工具里都会退化成"写脚本"。①档工具（如 MCGS）假设单品牌直连，对多品牌混合架构反而是倒退。

七、结合本项目（MachineMonitor）的过渡路线

7.1 分层判定

层现状判定
设备/控制层10 个 C# 子程序 + Omron FINS + Roders TCP 20200 + Siemens OPC UA禁止低代码——握手/时序/异常处理是核心资产
服务层MachineMonitor.exe :8888，Controller/Service/Repository 分层原样保留——它就是低代码的"数据源 + 超级 PLC 驱动"
页面层web-ui/frontend 双轨（sections 命令式 + Vue2 app.js）低代码接管区——该低代码化的部分

7.2 "拖一个键位直接下料"的实现路径

每个 C# 子程序就是一块已封装好的积木，且已通过 :8888 暴露为 REST 接口。低代码平台拖按钮调接口，即为"拖键位控设备"：

低代码页面拖按钮 ──POST /api/unload_machine──▶ MachineMonitor ──▶ C# 子程序 ──▶ PLC/机器人 │ │ └────────────── 轮询 GET /api/status ◀── workstate 回写 ◀────────────────┘

对低代码平台而言，自研后端就是一个"超级 PLC 驱动"——它不感知底层是 FINS 还是 TCP 20200 还是 OPC UA，只看到"调接口 → 动设备 → 回状态"。

7.3 四步过渡计划

#步骤工具工作量风险
①接口契约化：8888 接口整理成 OpenAPI/Swagger 文档已有 gen_doc.py，补齐即可小无
②先替换"读多写少"页面：料架看板、机床状态、机器人监控amis（JSON 配置渲染，纯静态文件可放 web-ui/frontend）中低——可随时退回 Vue 版
③再换配置/表单类：grippers 配置、rack_administrate 料位维护等 CRUD 页amis CRUD 组件 / 活字格中低
④可选：Node-RED 挂 MQTT/FINS 做采集管道试验Node-RED（免费）小低——仅编排层，不碰握手逻辑
迁移顺序原则：rackoperate/scan 联动页涉及实时状态刷新与异常路径，最后迁甚至不迁；从看板和配置页开始收益最大、风险最小。

八、三个提醒

  • 低代码不解决现有痛点：config.json 三份分发、GBK 编码、O0011 程序号冲突等是设备层/配置层问题，换页面框架碰不到。
  • 双轨并存是优势：frontend 里命令式版与 Vue 版本已并存，amis 作为第三轨零风险，新页面先用 amis，旧的按需迁移。
  • 警惕"整体迁移"话术：用 YonBuilder/奥哲整平台重写 = 丢掉全部控制层积累 + 适配其数据模型，对本项目不划算。
